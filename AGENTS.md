## What this project is

An installable offline PWA dictionary for Bulgarian ↔ English, powered by [WikiDict](https://www.wikdict.com) data (derived from Wiktionary).

- **Live app**: https://kfet.github.io/bg-en/
- **Current version**: 0.1.0 (see `VERSION`)
- **Stack**: Vite + vanilla TypeScript, Python data pipeline, GitHub Pages deploy
- **No backend.** Fully static. All search happens in-memory in the browser.

## Data pipeline

```
WikiDict SQLite (bg-en.sqlite3, en-bg.sqlite3)   ~18 MB download
  + kaikki.org Bulgarian JSONL                    Bulgarian IPA, gender, plural, aspect
  + ipa-dict en_US                                English IPA
  + UniMorph eng                                  English irregular forms
          │
          ▼  scripts/build_data.py  (~5 min, cached in scripts/.cache/)
          │
public/data/bg-en.json   46k entries, ~4 MB uncompressed
public/data/en-bg.json   65k entries, ~11 MB uncompressed
          │
          ▼  browser: src/search.ts
Binary search (O log n) over sorted in-memory arrays
```

**Data files are not committed.** They are in `.gitignore` and regenerated by GitHub Actions on every deploy. To work locally, run `python3 scripts/build_data.py` once; the SQLite files are cached in `scripts/.cache/` for subsequent runs.

## Data format

```typescript
// Entry: [written_rep, trans_list, sense_list, pos]
type Entry = [string, string, string, string]
// e.g. ["баба", "babushka", "", "n"]
// e.g. ["house", "дом | къща | помещение", "dwelling", "n"]

interface DictData {
  version: string            // WikiDict release, e.g. "2025-11"
  entries: Entry[]           // sorted ascending by entries[i][0].toLowerCase()
  meta?: Record<string, WordMeta>
}

type WordMeta = {
  ipa?:    string   // "/ˈhaʊs/" or "[ˈbabɐ]"
  gender?: string   // BG: 'm' | 'f' | 'n'
  pl?:     string   // plural form
  aspect?: string   // BG verbs: 'impf' | 'pf'
  paired?: string   // BG: paired aspect form
  past?:   string   // EN irregular: "went"
  pp?:     string   // EN irregular: "gone"
  cmp?:    string   // EN: "better"
  sup?:    string   // EN: "best"
}
```

**Invariants:**
- `entries` is sorted by `entry[0].toLowerCase()` — binary search depends on this
- Multiple entries may share the same `written_rep` (different POS)
- `trans_list` separator is ` | ` (space-pipe-space)
- Valid `pos` values: `"n"`, `"prop.n"`, `"v"`, `"adj"`, `"adv"`, `"prep"`, `"part"`, `"num"`, `"interj"`, `"pron"`, `"conj"`, `"det"`, `""`

## Architecture decisions (final — do not revisit)

| Decision | Choice | Why |
|---|---|---|
| Data format | Sorted JSON arrays, not SQLite | Zero browser deps, works everywhere, GitHub Pages compatible |
| Search | In-memory binary search | O(log n), instant after load, no index needed |
| Framework | Vite + vanilla TypeScript | Minimal bundle, no framework overhead |
| PWA | vite-plugin-pwa (Workbox) | Pre-caching, auto-update, battle-tested |
| Deployment | GitHub Pages via GitHub Actions | Free, HTTPS, no server |
| Data committed? | No — generated in CI | SQLite is 18 MB, JSON is 15 MB — too large for git |

## CI/CD

- **Push to `main`** → GitHub Actions runs: `build_data.py` → `npm test` → `npm run build` → deploy to Pages
- **Monthly cron** → `check-data-update.yml` detects new WikiDict releases and opens a PR automatically
- **Data cache key** in `deploy.yml` is keyed to the WikiDict version string; changing `VERSION` in `build_data.py` invalidates the cache and forces a fresh download
